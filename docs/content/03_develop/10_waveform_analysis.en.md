
# Waveform Analysis Format and Extensions

`WaveInfo` automatically selects a reader based on the file extension, with built-in support for FST, VCD, and FSDB. File listing, signal query, event analysis, and evidence replay all use the same format configuration. This configuration only affects the search and selection of existing waveforms during analysis; it does not change the format generated by the simulator, `SetWaveform`, or test fixture.

## Default Suffixes for Test Artifacts

The test API template selects the artifact suffix via `ucagent.get_default_subfix(dut, sub_type)`, where `sub_type` is either `"waveform"` or `"coverage"`. The returned value does not include a leading dot:

| `dut.SIMULATOR` | Waveform Suffix | Coverage Suffix |
| --- | --- | --- |
| `verilator` | `.fst` | `.dat` |
| `vcs` | `.fsdb` | `.vdb` |
| `uvs` | `.usdb` | `.cdb` |

This function accepts a DUT instance or class, reads the simulator name from its attribute, and ignores case and leading/trailing whitespace. If the `SIMULATOR` attribute is missing, it defaults to Verilator. If the attribute is `None`, an empty string, a non-string, or an unknown name, an error is raised; an invalid `sub_type` also raises an error.

`get_coverage_data_path(request, dut, new_path)` and `get_waveform_path(request, dut, new_path)` return the suffixes used for unique artifact paths for each test. When creating artifacts, use `new_path=True`; when reporting coverage, use the same DUT with `new_path=False` to obtain the original path. For VCS, `.vdb` may be a directory; pass the full path. The fake DUT in the template phase and independent Mock DUTs retain the `SIMULATOR` declared in the original DUT class without needing to start a real simulator.

When adding a new simulator, add `waveform` and `coverage` to `_SIMULATOR_DEFAULT_SUFFIXES` in `ucagent/util/test_tools.py` and add the corresponding tests; no branches need to be added to the path templates. This mapping only defines naming rules; actual artifacts depend on DUT build and simulator support. New waveform formats still require registration of a reader as described in this page. Coverage parsing is provided by `toffee-test`, and when using VCS, ensure the used version supports `.vdb`. Selecting suffixes itself does not add coverage parsing capabilities.

## Format Priority

The default configuration is located in `ucagent/setting.yaml`:

```yaml
runtime_options:
  waveform_analysis_format_priority: [fst, vcd, fsdb]
```

This can be overridden in workspace configuration or an explicitly specified configuration file, for example, to prioritize VCD analysis:

```yaml
runtime_options:
  waveform_analysis_format_priority: [vcd, fst, fsdb]
```

The list defines the formats participating in the search: `[vcd]` searches only for VCD, disabling FST and FSDB. The list must be non-empty, extensions must be lowercase and without a dot, and duplicates are not allowed. This configuration follows the normal configuration hierarchy; the parsed value is written to `runtime_options` in `.ucagent/runtime_config.json` and is not re-read from environment variables at runtime.

`WaveInfo` first determines the latest `toffee_tmp_*` test session, then matches the exact test name and optional numeric dump suffix. Within the same session, it compares format priority first, then numeric suffix, file modification time, and path. Therefore, under default configuration, `test_add001.fst` takes precedence over `test_add999.vcd`. It will not use an older session to find a higher-priority format, nor will it replace the test name with a similar one. File extension case does not affect format recognition.

If the selected file is empty, corrupted, or missing parsing dependencies, the tool returns the file's path, format, and recovery suggestions without automatically switching to another format. To switch, first fix waveform generation or explicitly adjust analysis priority, then re-call `WaveInfo`. The `format_priority` in the listing and selection results displays the order used for the current analysis.

## FSDB Runtime Dependencies and Online Viewing

FST, VCD, and FSDB use `wavekit`'s `FstReader`, `VcdReader`, and `FsdbReader`, respectively. FSDB also requires the Verdi NPI runtime library `libNPI.so`; configure it before starting UCAgent using one of the following methods:

- `WAVEKIT_NPI_LIB`: The full path to `libNPI.so`.
- `VERDI_HOME`: The Verdi installation directory.
- `LD_LIBRARY_PATH`: A search path containing the library and its runtime dependencies.

These variables are used by the FSDB runtime library and operate independently of the waveform analysis format priority configuration. If NPI is missing, `WaveInfo` reports to the verification task that waveform analysis cannot be performed and recovery actions are taken; the underlying exception is written to the UCAgent runtime log. Environment maintainers should check runtime library configuration according to this section. Format, reader, and dependency configurations are managed by environment maintainers. Runtime guides and tool descriptions only require the verification task LLM to call `WaveInfo` and handle the results.

The current browser viewer supports FST and VCD. FSDB can be queried and analyzed via `WaveInfo`, but it will not generate online viewing links that cannot be opened. When final bug evidence requires an online viewing link, first export to FST or VCD, configure it as the preferred format for analysis, and then re-execute the final `WaveInfo`. Directly accessing the logic viewing interface and selecting FSDB returns an HTTP 415 error, preventing the opening of a waveform in another format. Final evidence must still follow the signal group, analysis window, and receipt requirements in `Guide_Doc/dut_bug_analysis.md`.

## Registering Other Formats

Register new extensions via the public interface `register_waveform_reader(format_name, factory)`. Registration should be explicitly performed during application or plugin initialization and must be completed before creating `WaveInfo`. A format can only be registered once; it cannot override built-in readers. After registration, the format name must also be added to the analysis priority.

```python
from ucagent.tools import WaveInfo, register_waveform_reader
from my_waveform_backend import WlfReader

# WlfReader accepts a file path and implements the reader contract below.

register_waveform_reader("wlf", WlfReader)

tool = WaveInfo(
    workspace="/path/to/workspace",
    test_dir="unity_test/tests",
    format_priority=["fst", "vcd", "fsdb", "wlf"],
)
result = tool.analyze(test_case_name="test_add")
```

When integrating with the full UCAgent workflow, use the same registration call and configure:

```yaml
runtime_options:
  waveform_analysis_format_priority: [fst, vcd, fsdb, wlf]
```

The `factory(path)` function accepts a waveform file path string and returns a context manager. Upon entering the context, the returned object must comply with the `wavekit` reader interface:

- `begin_time`, `end_time`: Integer simulation timestamps.
- `top_scopes`: Each scope provides `full_name`.
- `get_matched_signals(pattern)`: Supports query syntax used by WaveInfo, returning a signal mapping. Signals provide `full_name`, `base_name`, and `width`.
- `_load_value_changes(signal, value_mapping, begin_time=None, end_time=None)`: Returns a 2D sequence of timestamps and mapped values. It must apply the passed 0/1/X/Z mapping; the start time should retain the previous most recent state, and the end time should be an open interval. WaveInfo reads values, X masks, and Z masks separately.
- When exiting the context, close files, native handles, and other resources, including paths where analysis failed.

Adapters can inherit the `wavekit` reader base class to implement these capabilities. Additional dependencies are loaded during factory calls, avoiding initialization of native runtime libraries merely by importing tools or listing files. Extended formats share existing discovery, analysis, receipt, and replay workflows; registering a reader does not extend the browser viewer's decoding capabilities.
