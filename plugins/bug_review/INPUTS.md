
# Bug Review 输入

提供一个包含 `unity_test/` 的源工作区。报告文件名、表格列和 Markdown 标签不固定；原始材料完整复制到 `{OUT}/inputs`，不先规范化或改写。

```text
source/
├── unity_test/
│   ├── 任意原始Bug报告.md
│   ├── tests/
│   └── 测试依赖的数据或配置
├── uc_test_report/          # 可选，导入时明确标为历史证据
├── <dut>/                  # 可选运行包；实际复跑需要与当前Python匹配
├── <dut>_RTL/              # 独立RTL源码
└── 独立规格或接口文档
```

第二阶段 LLM 阅读材料后，通过 SubmitReviewClaims 生成统一声明和 Case 关联，不根据固定标签自动决定 Bug 数量。来源缺失、格式不明确或测试无法关联时，保留声明及具体缺口。

默认只复跑关联测试，不要求先全量收集。参数化用例以真实 pytest 收集结果为准。输入测试及断言不得修改；执行使用 `{OUT}/runs/work` 副本，并保留测试所需数据和配置。

缺运行包、规格或源码时可以开展资料复核并形成未定结论。历史测试报告只证明其标明运行的结果，不能称作本次复现。报告中的源码摘录或根因说法不能作为独立源码核实。

每次运行使用新的目标工作区。输入与输出不能互相嵌套，准备工具拒绝符号链接和已有目标，避免覆盖原始资料。不要将 API Key 或其他不需要的私有文件放进待复制源目录。

## 通用参考资料

首次运行前，在插件目录执行 `python3 scripts/download_standards.py`，下载完整香山设计文档、RISC-V 手册和 Chisel 文档；第三方文档不随 Git 仓库提交，也无需每个模块重复准备。启动时归档到 `{OUT}/inputs/review_standards/`；原输入不能占用 `unity_test/review_standards`。可另提供项目专用规格补充配置和接口约定。适用通用条款足以支持确认 Bug，缺专用 Spec 不自动判未定；具体引用必须指向原文条款与行号。
