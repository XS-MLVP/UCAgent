
# 功能验证要求

按本文件生成 reference、API 和测试。功能依据为 `01_design_specification.md`，全部 DUT 交互必须经过 `02_interface_and_timing.md` 的公共顶层引脚，不增加内部硬件观察点。

## 1. Python reference 与测试边界

Python reference 必须实现真实编码解码、块内精确归约、块贡献舍入、顺序 FP32 累加、Bias、激活、配置和握手状态机，不能用预存答案、RTL 输出或固定 smoke 返回值代替计算。

有限数建议用整数乘二的幂或有理数表示；独立实现 RNE、subnormal、overflow 和 canonical NaN。不得把普通 Python `float` 连加、NumPy `matmul` 或近似误差阈值当作位精确 golden。数值 oracle 从输入计算 expected，与 DUT adapter 的状态和输出独立。

reference adapter 暴露与 RTL 相同的引脚接口，任何高层 API 都通过引脚驱动完成事务。测试中禁止直接调用 reference 的矩阵运算方法作为 DUT 请求、读取内部结果缓存或使用 backend 私有的完成状态。时钟推进、波形开启等仿真控制可以由 fixture 提供，但不能借此读取隐藏功能状态。

reference 可以使用自己的合法延迟。使用当前阶段提供的测试工具，在 Python reference 和 RTL 上执行相同测试，不修改断言、不增加根据被测实现跳过检查的分支；比较接受的输入、输出、配置读回和协议约束，不要求内部状态或逐周期 ready 轨迹相同。

## 2. 共享测试 API

在 `{OUT}/tests/` 生成以 `api_npu_pe_core_` 开头的共享 API，首个参数为 `env`；会等待的函数以 `max_cycles` 为最后一个参数。至少提供复位、配置读写、配置高层校验、请求启动、发送数据包、接收结果行和完整 tile 操作。

- 驱动输入必须检查参数位宽和合法值，按引脚的 ready/valid 保持规则发送。
- 每行返回的数据、行号、状态和完成事件均来自引脚采样；不能从 expected 构造返回值。
- 超时抛出 `TimeoutError`，并给出最后观察的引脚状态和已完成的包 / 行数。
- 输入形状或编码错误抛出 `ValueError`；NaN / Inf 等合法编码不得误拒绝。
- 高层 tile API 必须恰好消费 `ARRAY_M` 行并验证行序，不能遇到第一行就返回。
- 保留低层引脚 / 配置操作，支持反压、非法配置、busy 期间写配置和复位取消测试。

测试记录由公共输入和实际握手组成的事务 trace。周期计数来自 `clk`，输入计数来自 `data_valid && data_ready`，结果计数来自 `psum_out_valid && psum_out_ready`，完成以最后一行消费和 `done` 的一致性确认。

## 3. 数值定向测试

必须实现 `01_design_specification.md` 第 4.5 节的独立向量和 `02_interface_and_timing.md` 第 3.4 节的打包向量，并覆盖：

| 类别 | 必需检查 |
|---|---|
| FP4 码本 | 16×16 个输入编码组合，含正负零，在 K=1 事务中隔离检验 |
| FP8 码本 | 两种格式的全部 256 编码都出现；覆盖指数全 1、边界尾数及混合格式两个方向 |
| 普通数 | 正负、零、最小 / 最大正规数、最小 / 最大 subnormal、最大有限值 |
| 非有限数 | NaN payload / 符号规范化、正负 Inf、`Inf*0`、同块和跨块异号 Inf |
| Scale | `0x00/0x01/0x7e/0x7f/0x80/0xfe/0xff`，两端极值组合及 bypass |
| 舍入 | 正 / 负 half ULP、偶数与奇数尾数 tie、FP32 正规 / subnormal 交界、下溢和溢出 |
| 归约 | 大数抵消后保留小数、同块次序变化等价、跨块舍入顺序反例 |
| 后处理 | Bias 正负 / subnormal / NaN / Inf；Bypass、ReLU、ReLU6 的负值、零、6 附近和非有限值 |
| 零优化 | 全零块、部分零块、零乘 Inf、零块配 NaN scale；确认异常不被零检测遮蔽 |

所有结果逐元素比较完整 32-bit 编码，包含 canonical NaN 和零符号规则。某个块贡献舍入为负零后，后续 `ADD32(+0,-0)` 的精确零规则可能将其规范化为 +0；expected 必须执行完整流程。

至少有一个用例在单个输出位置注入差异，确认该差异只按 A 行、B 列及 scale 适用范围传播；不能只用各行各列相同的矩阵掩盖连线或转置错误。

## 4. 协议、寄存器与时序测试

全部检查通过顶层引脚进行：

- 逐寄存器复位值、读写掩码、只读写忽略、保留位、未定义与未对齐地址。
- 非法格式码、FP4/FP8 混合宽度、K=0/4097/65535、非法激活抑制启动；修复配置后可正常执行。
- start 只在 ready 时接受，配置写优先，busy 期间的 start 和配置写不改变当前事务。
- 输入 valid 气泡不推进 K；首包和块首包在等待时保持全部负载；非块首包的 scale 改变不影响当前块。
- K 取 `1,3,4,7,8,9,31,32,33,63,64,65,1023,1024,4095,4096`，覆盖两种打包宽度、边界和尾 lane 忽略。
- 输出按行有序且不重复；反压下 valid / row / data 稳定；最后一行反压时 busy 不撤下、done 不提前。
- 最后一行握手后 done 恰好一个周期，STATUS sticky 位正确；紧邻事务以及 FP4/FP8/混合格式切换无污染。
- 空闲、收数、块交界、等待结果和已输出部分行时复位；复位取消整个事务，恢复后没有旧结果或旧 done。
- 输入和输出长期等待后恢复仍能完成；所有驱动和等待有显式超时，超时按失败处理。

测试必须覆盖真正观察到的输入反压；如果某个实现始终能接受当前 workload，可通过更长合法连续输入验证其无丢失行为，不得伪造 `data_ready=0` 事件。检查内部是否使用 FIFO / skew / ping-pong 不属于功能测试。

## 5. 随机与参数化回归

五种格式组合每种至少 32 个确定性随机 tile，使用固定 seed。覆盖不同 K、行列差异、逐块 scale、尾部填充值、输入气泡和输出反压；另设定向边界测试保证随机不易命中的异常语义。

同一事务必须在不同合法气泡 / 反压计划下得到相同结果。完整保存输入、配置、seed 和失败引脚 trace，失败不能通过换 seed 或修改 expected 消除。

1×1、2×3、4×4 和 8×8 参数 smoke 至少覆盖 FP4、FP8、K=33、尾 lane、行列打包和结果行号宽度；PPA 的固定工作点为 4×4。每种参数配置都仅通过对应宽度的公共引脚交互，不依赖内部模块数量。

## 6. 覆盖与通过标准

生成 FG/FC/CK 时把数值、配置、协议和边界要求映射为可观察的检查点。对本文件中的测试过程要求，可使用说明责任产物的 `IGNORE` 行映射，不要制造内部 DUT 功能。

Toffee 功能覆盖至少包含五种格式、scale 开关和边界、K / block / tail 分类、特殊数、三种激活、配置非法与恢复、复位阶段、输出反压和完成状态。覆盖采样来自引脚或由输入推导的类别，不能根据测试名称无条件宣称命中。

功能通过需要所有规定检查点都有真实用例和断言，并在 Python reference 和 RTL 上通过。代码覆盖用于寻找遗漏；不得制造不可见内部要求、弱化正确断言或跳过困难向量来满足覆盖。规格未要求综合、布局、FPGA 或 DFT 级工具作为功能测试前置条件。
