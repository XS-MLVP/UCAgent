
# AI agent 执行指南

本文供接收 README 一句话任务的 AI agent 使用。你的职责是准备启动条件、实际调用 UCAgent、
跟踪任务并交付结果，不是绕过 UCAgent 的阶段和检查自行写一套资产后宣称工作流完成。

## 1. 解析用户请求

从用户的话中取得工作流、目标、工作区和输入来源。先定位当前 UCAgent 仓库，所有相对路径都转换为
明确的实际路径；不要假定终端当前目录就是仓库根目录。

| 工作流 | 目标 | 默认输出目录 | 详细说明 |
| --- | --- | --- | --- |
| `privileged-suite-generation` | Test Suite | `act4_assets` | [场景型生成](generation.md) |
| `unprivileged-suite-generation` | Test Suite | `act4_assets` | [表驱动指令生成](generation.md#非特权指令生成) |
| `xiangshan-v3-handoff` | 香山模块，如 `Vector` | `act4_xiangshan` | [香山交付](xiangshan.md) |

两个生成工作流的目标必须取自 [Test Suite 目录](test-suites.md)，使用代码格式的标识并精确匹配大小写。
CLI 标识不是原生文件名；组合目标需保留完整范围。生成路线按是否需要 trap 或非规则状态序列选择，
不能仅凭扩展名称判断；发现用户指定的路线不适合时，解释原因并确认切换，不擅自缩减测试内容。
香山目标不受该目录限制，但交付的是整核架构测试资产，不是独立微架构模块的接口级 UT。

生成流程先按 [配置指南](run-configuration.md) 创建或复用运行 YAML，落实每类来源与处理策略。
默认改进上游、缺失则生成；不要求用户预先填写源文件清单或命令。香山仍使用其独立输入配置。

## 2. 启动前准备

外层 AI agent 可以是 Codex、OpenCode 等；本指南统一让 **UCAgent 使用 `codex` 后端**。
外层 agent 负责启动和观察，UCAgent 调用 Codex CLI 推进内部阶段。因此即使用 OpenCode 发起任务，
也必须先确认 Codex CLI 在 UCAgent 的 PATH 中可用，并已配置可用的模型访问。

需要 Python 3.11+、UCAgent `>=26.9.2.dev25`、ACT4 插件及 Git。优先复用已有兼容 Python 环境，
缺失时在专用虚拟环境中安装；不要为了执行任务替换系统 Python 或直接升级全局环境。
以下命令从 UCAgent 仓库根目录、在选定 Python 环境内执行；已有兼容安装可跳过对应安装步骤：

```bash
python3 -m pip install .
python3 -m pip install ./plugins/ACT4
ucagent --list-plugins
ucagent --validate-plugin act4
command -v codex
codex --version
```

使用当前源码时，可通过 `--plugin /absolute/path/to/UCAgent/plugins/ACT4` 加载，避免意外运行旧安装版本。
源码核心若显示 `0.9.1+source.code`，先安装核心生成版本元数据，不要降低插件版本要求，见
[源码与安装态](development.md#源码与安装态)。插件注册本身不下载编译器或参考模型。

模型认证由用户或运行环境提供；需要登录、授权或额度补充时明确请求帮助，不读取或打印密钥。
检查 `ucagent/setting.yaml` 及用户覆盖中的 Codex 后端命令和执行权限；仓库默认命令含 `--yolo`，
应在用户授权的受控环境中运行，不把工作流目录约束当作操作系统沙箱。
不要擅自覆盖用户的全局 Codex 配置、扩大权限或购买商业工具许可。

## 3. 实际启动 UCAgent

生成任务使用统一入口，不再拼接环境变量：

```bash
act4-run /absolute/path/run.yaml --print-command
act4-run /absolute/path/run.yaml
```

启动器设置 Codex、MCP、自动循环、完成退出和配置中的端口/Skill 开关。
必须实际运行，打印命令或创建 YAML 不算已执行工作。香山按 [独立指南](xiangshan.md) 启动。
将进程放在可持续跟踪的终端任务或后台会话中，记录实际命令、工作区、进程/会话标识和日志位置。
不要因单次终端调用的等待时间到期而另开重复任务。需要保留启动日志时，放在工作区的运行资料目录，
不要混入最终交付压缩包。

两个生成工作流会在准备资源前校验目标，并在终端显示 suite 的来源及基本信息。
随后由工作流探测工具、复用共享资源并准备缺项，详见 [环境准备与复用](environment.md)。
不要在外层预先重复 clone 整库、安装所有工具或替内层写环境验收结果。
工具安装需要网络或权限而当前不可用时，报告具体请求；商业工具缺失按工作流规定记录为限制。

## 4. 跟踪、恢复和完成判定

- 用 `act4-status <工作区>` 查看最近正式 Check/Complete，结合最新日志区分正常长任务、等待输入、模型失败、阶段验证失败与已完成。
  正在运行只能报告进度，不能报告已经生成完毕。
- 阶段由 UCAgent 内部使用 `CurrentTips`、`Check`、`Complete` 推进并维护 journal。
  不替它编辑完成标记、不使用强制跳阶段参数、不伪造命令日志或修改校验来掩盖失败。
- 如果模型认证、额度或确实缺少的外部输入阻塞任务，给出阶段、具体原因、影响与所需帮助；
  不无限重启。用户要求停止时终止本轮相关进程并保留恢复资料，不误杀其他任务。
- 中断后，确认旧进程已结束，再使用同一工作区、目标、输出、输入和工作流参数恢复。
  沿用阶段历史与 journal；不加 `--no-history`，不清空工作区，不重写旧证据。
- 只有工作流显示全部阶段完成，且最终产物及其验证记录存在、互相一致，才能报告工作流完成。
  单独的退出码、已有 `final.md` 或生成了一个压缩包都不足以证明本轮完成。
- 两个生成流程连续 3 轮无进展默认暂停；先处理相同诊断的根因，不自动反复重启。
  checker 参数接口等运行环境故障不能通过改测试计划、删场景或扩大 timeout 修复。
  代码修复后需重启进程；输入范围契约改变时用新工作区，不手改旧收据或阶段完成状态。
- 若启动日志提示项目指令预算耗尽、工作区 AGENTS 被跳过，先解决本轮 Codex 指令加载问题，
  再执行资产任务。不要擅改全局配置，或误把这类启动警告当作工具验收成功。

## 5. 给用户的最终答复

先用几句话解释完成了什么、修复或生成了什么、仍有哪些限制及需要用户协助的事项，再给实际文件路径：

- 两个生成工作流：`<工作区>/<输出目录>/final.md` 和 `changes.patch`。
- Review：同样交付 `final.md`、`changes.patch`，说明发现、已修复、未修复及原因。
- 香山交付：报告中列出的实际交付目录及压缩包，并说明接收方操作指南的位置。
- 计划、日志、验证证据位于输出中的 `intermediate/`，只在解释结论时引用，不重复打包给接收方。

区分“资产生成/修复完成”“本地原生验证通过”“商业 coverage 已验证”和“真实 DUT 已运行”。
未执行某项验证就明确写未验证；表格状态、模型口头判断和成功安装工具都不能替代运行证据。
