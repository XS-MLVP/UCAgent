
# 已有资产的增量生成

审查是两个生成工作流的公共阶段。根据原生生成机制选择场景型或表驱动路线，默认逐类检查上游资产、
补齐缺失内容；复查本地结果时在 [统一配置](run-configuration.md) 中给对应类别设置
mode: improve、source: local 和原输出目录。

## 流程与结果

1. 只根据 ISA 和用户范围独立设计，再读取已有测试，降低既有计划遗漏带来的引导。
2. 冻结每类来源；本地原目录只读，补丁需精确基线重建，本地缺源不能静默退回上游。
3. 基线审查比较 ISA 义务、计划、覆盖、生成器和原生验证，把缺口转成生成或修复工作。
4. 在副本实现并隔离验证，保留发现、前后证据和未解决原因；无需改动则保留原内容。
5. 根目录 final.md 汇总结果、九类 checklist、来源策略及所需协助，changes.patch 相对导入基线生成。

命令及示例见 [运行配置](run-configuration.md)。scope/review/final 格式在运行时
Guide_Doc/ACT4_Extension_Review_Guide.md，由 agent 填写，无需用户预先准备。
商业工具可选，未运行不能标为通过；缺免费工具或实现通常是待补全工作。
审查可保留 deferred/not_fixed 和部分成果，但整轮成功仍要求适用的必需生成与验证通过。
