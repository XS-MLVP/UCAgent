
# ACT4 执行准备检查与局部计时

本项属于 ACT4 `extension-review` 工作流，目的是在完整取证前发现执行准备问题，减少因
解释器、工具版本、导入来源、工作目录或启动程序错误而进行的无效原生执行。
修改基于 `f5293881`，不涉及核心 TUI、请求重试、报告完整预检或生成产物清理。

## 修改范围

新增 `Check(stage_args={"prepare_environment": true})`，用于 inventory/audit。
复用声明的环境 probe、按需 install 和安装后复验，在隔离副本中执行；解释器、版本和
模块来源由当前 ACT4 提交对应的真实 probe 校验，不在插件中硬编码版本或目录布局。
准备检查不运行其余原生 lane，单独保存 `execution-preparation.json`、开始时间、耗时和日志。
具体调用、状态和恢复动作以
[运行指南](../src/act4_privileged_suite/Guide_Doc/ACT4_Extension_Review_Guide.md) 为准。

完整取证也先完成全部 environment jobs，再运行其他 lane，环境任务只依赖其他环境任务。
命令启动前检查 cwd 和 argv[0]，包括按子进程 cwd 解析相对 PATH。
准备阶段对可能由原生前序任务创建的缺失目录或程序标为 deferred，正式执行仍检查。
无法静态确认的参数、包装命令内部程序、生成结果和实际测试有效性仍须完整执行验证。

准备报告和日志不覆盖正式证据、审查报告或授权摘要；正式取证仍重新探测环境。
准备模式不能 Complete、不能与 run_commands 同用，也不改变人工授权门。
未执行和失败的必需 CI 保持原有审查语义：如实记录并交付审查，不能宣称验证通过。

## 合成对照

同一 Python 环境、同一六 job 合成 scope，每项原生命令人为增加 0.1 秒等待；
对照读取 `f5293881` 的原始模块，前后交替执行，各测 5 次。
初次 inventory 冻结不计时，后续 scope 校验、基线核对、隔离 clone 和运行均计入。
没有模型 API 调用、真实 ISA 测试或阶段历史操作。

| 场景与操作 | 中位数 | 最小—最大 |
| --- | ---: | ---: |
| 合法输入，修改前完整取证 | 1364.6 ms | 1194.5—1686.5 ms |
| 合法输入，修改后完整取证 | 1422.5 ms | 1145.0—2061.4 ms |
| 合法输入，修改后准备检查 | 178.7 ms | 110.4—528.9 ms |
| 最后一个 lint job 的 cwd 缺失，修改前完整取证 | 1811.6 ms | 966.8—3934.4 ms |
| 同一 cwd 错误，修改后完整取证 | 1623.9 ms | 985.3—3977.4 ms |
| 同一 cwd 错误，修改后准备检查 | 111.3 ms | 92.7—803.3 ms |

在该合成错误场景中，发现错误的操作耗时中位数下降约 93.9%，原因是可以单独检查准备，
不再先运行前四项原生任务。两种操作的工作量不同，不能将该比例当作完整取证或完整
workflow 的加速。合法输入的完整取证没有显示加速；运行时存在其他原生编译任务和插件
回归测试并行负载，样本波动较大，不能据此判断小幅性能变化。

前后完整取证的 job 状态、ELF 输入数、实际通过数和产物字节摘要一致，包括故障输入；
这只验证所测执行结果的保留，不证明真实扩展的语义正确性。
若新增一次成功的准备检查后仍完整取证，会增加一次隔离和探测开销；收益主要来自提前
修复准备问题及减少返工，需另做同模型真实阶段对照才能量化。

重现命令（仓库根目录，使用已安装核心及插件测试依赖的 Python）：

```bash
PYTHONPATH=.:plugins/ACT4/src act4-run-01/.venv/bin/python \
  plugins/ACT4/tests/benchmark_execution_preparation.py \
  --base-ref f5293881 --repeats 5 \
  --output /tmp/act4-execution-preparation-benchmark.json
```

本轮原始样本保存在 `/tmp/act4-execution-preparation-benchmark.json`，包含代码摘要、开始时间、
全部样本和限制。临时目录中的合成输入已清理，没有改写现有 ACT4 运行目录。

## 验证范围

覆盖 inventory/audit 准备模式、非法参数和阶段、环境依赖排序、安装和复验、版本及模块来源、
超时、相对 PATH、无效 cwd/不可执行程序、前序生成路径的延后检查与正式复查、诊断数量上限、
已有证据不被覆盖，以及工具持久化后仍重新探测。
真实阶段测试分别开启和关闭 Skill，关闭时没有 Skill 目录，验证准备调用、普通 inventory
Complete、准备模式不能 Complete，以及 audit 不能用准备报告代替正式证据。

插件全量回归 638 项通过；全量收集后补充的版本/导入来源与环境依赖组合另做 6 项定向测试，
全部通过。Python 编译、默认/显式规范路径下的工作流 YAML 解析与 checker 实例化、
`git diff --check` 及现有文件换行格式检查均通过。
