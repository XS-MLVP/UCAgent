
# 工作流的环境准备与复用

三个工作流都在执行测试资产生成或构建前运行 `prepare_environment`；香山交付先完成
`handoff_scope` 的源码准备与功能范围选择，以确定实际依赖。用户提供选定版本的输入源码和规范，
香山交付也可将缺失的默认 checkout 下载到自身输出目录；AI 读取
该版本的依赖清单及 CI 安装说明，生成工具计划，执行真实探测、缺项安装及安装后复验。
UCAgent、ACT4 插件和模型连接需要在启动前可用，工作流不会安装自己的运行宿主。

## 安装位置

1. 先探测当前 PATH 中的软件，版本/能力匹配就直接复用，包括已经安装到系统的软件。
2. 缺失软件默认安装到 `~/.local/share/ucagent/act4/tools/<工具>-<配方摘要>/`。
   这是持久化用户安装，通常不需要管理员权限；同用户下后续工作区和模块可复用，使用前仍然探测。
3. 存在版本冲突、需要试验或不宜长期保留的依赖，设置 `storage: temporary`，安装到
   系统临时目录下的 `ucagent-act4-<uid>/<工具>-<配方摘要>/`。不会覆盖已有工具或更改系统默认版本。

无需为每轮重新下载编译器和模型。安装命令依据输入项目选定版本编写，不强制追随“最新版”。
可以复用管理员安装的系统软件；默认自动安装选择持久化用户目录，以避免升级系统 Python、
改变系统编译器或修改 shell 启动文件。安装脚本必须尊重 `{PREFIX}`，不得用 sudo、
全局 pip 或无范围的包管理器升级替换现有环境。

项目自己的 Python 依赖仍按锁文件同步到工作副本的虚拟环境，并复用包下载缓存。
尤其 review 不共享指向其他源码的 editable 环境，也不写入原始输入；这类副本环境不是重复安装
全套公共工具。需要额外原生库或工具时，首阶段计划可增加工具条目并指定相应安装前缀。

## 执行、证据与失败处理

环境阶段首先实测 Python、Bash、Git、Curl、Make、uv、编译器、模型、lint 和商业仿真器的可发现性。
AI 根据实际依赖补充安装计划，`Check` 执行计划并保存退出码、版本输出和安装日志。
成功退出但版本不符仍不算准备完成。共享安装有进程锁；另一个任务正在安装时记录重试动作。

产物位于 `<OUT>/<模块>/environment/`：`host.json` 是初次探测，`plan.yaml` 是安装计划，
`receipt.json` 和日志是实测证据，`summary.md` 是摘要，`activate.sh` 用于后续 shell 命令。
review 和香山原生命令自动使用准备好的 PATH；生成流程及外部代理执行 shell 时先运行：

```bash
source act4_assets/Sstc/environment/activate.sh
```

按实际输出路径替换。环境只传给对应任务的子进程，不修改 UCAgent 进程的全局 PATH。
收据、计划、日志和工具被替换或临时目录消失时需重新准备，不能复用不再适用的证据。

缺少公开工具但还未提供安装方法时，环境阶段要求先补全计划。真实安装受网络、权限或
平台限制失败时，保存原因和恢复动作，允许继续可执行的审查与生成；依赖它的构建/执行仍按
各自门槛记录失败或未验证，不自动变为通过。没有公开安装路线时必须说明具体缺项。
最终报告应引用环境摘要，写明影响及用户能提供的帮助。安装耗时可通过 `StdCheck` 查看，
`KillCheck` 会终止当前安装进程组，保留日志。中断后可重试，兼容的完整安装会被复用。

Questa/VCS/Xcelium 仅探测，不自动安装、不作为普通流程的必需依赖。review 还会执行最小
covergroup 编译/仿真探测许可证与功能；这不等于 ACT 原生 coverage 验证通过。
香山 emu 由用户提供，不由环境阶段自动构建整个 RTL 项目。

审查流程的环境阶段只读安装资料，不接触已有 CTP、coverage、testgen 或测试内容；
独立 ISA 计划冻结后才分析现有测试，避免环境准备打破独立设计顺序。

安装计划完整格式见 [环境运行指南](../src/act4_privileged_suite/Guide_Doc/ACT4_Environment_Guide.md)。
