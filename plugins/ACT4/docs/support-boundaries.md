
# 按 Test Suite 从规范补齐 ACT 资产

## 1. 支持的含义

用户可以按 [ACT 进度表][sheet] 的 **Test Suite 列原名**提出需求。两种生成工作流的目标
都是从规范补齐所需资产，不是只运行已经齐全的上游测试。没有现成 testplan、CTP、
coverpoint、norm/param mapping、testgen、模板、formatter 或解码支持，属于要完成的工作，
**不能据此判定该 Test Suite 不支持**。

同样，缺少免费工具、参考模型、设备激励、观察接口或适配器，应先判断能否安装、复用或
在 suite 内实现并验证。此处的实现任务不授权重写共享定义或新增 Sail 语义；确需上游提供能力时，记录受影响范围和待办，不把它记作通过。

“纳入生成范围”不等于“已经逐项验证可全自动跑通”。真正完成一轮运行后，才能报告该
范围内生成了什么、哪些检查通过、还缺什么外部输入。表格中的供应方进度也不是插件的
验证结果。完整原名索引见 [Test Suite 工作清单](support-inventory.csv)。

九类贡献资产的复用、修复、报告以及跨项目补丁和验收规则见
[生成流程的九类资产说明](generation.md#5-九类资产的按需补全)。最终 checklist 的状态来自本轮
实际检查；配套能力按需补全，不要求每个 suite 都重新实现整个模型或接口。

## 2. 两种生成路线共同承担的工作

1. 定位固定版本规范及相关章节，先独立分解行为与边界，再核对既有资产。
2. 明确 Test Suite 原名、原生计划、生成入口、XLEN、SEW 和交互扩展的关系。
3. 缺什么补什么：计划、覆盖、映射、参数、CTP、生成器、模板和配置均可新建或完善。
4. 安装免费软件；需要时编写参考模型、适配器、设备激励和观察代码，安排独立反例与回归。
5. 实际运行补全检查及原生生成、编译、执行等验证；失败继续修，不能以文档声称替代结果。
6. 最终摘要分别报告资产补全、验证程度、商业许可限制和具体外部帮助请求。

表驱动普通指令使用 unprivileged-suite-generation；需要异常处理或状态序列的行为使用
privileged-suite-generation。带异常的向量矩阵不能通过省掉 trap 场景改成普通指令测试。
启动方法见 [生成工作流](generation.md)，完整补全计划及检查契约见
[运行指南](../src/ucagent_act4/Guide_Doc/ACT4_Checker_Guide/ACT4GenerationCompletionChecker.md)。

## 3. 常见缺项应如何处理

| 类型／示例 | 工作流应当完成的事 | 不能误称为什么 |
| --- | --- | --- |
| 没有计划或生成器的 suite | 从原文建立计划并实现原生生成器 | “没有上游资产，所以不支持” |
| `Zacas`、`Zfa`、`Zfh`、`Zfhmin` 等指令变体 | 按 Instruction、Type、ExtraExtensions 区分合法请求 | “同名指令重复，模块不支持” |
| `Vx8/16/32/64`、`Vls*`、`Vf*` 等 | 解析父计划与位宽，使用 EFFEW 元数据及原生模板展开，核验全部请求范围 | “没有同名 CSV，所以不支持” |
| `E` | 复用 I 的原生计划，选择 E 入口及 rv32e/rv64e 产物 | “没有 E.csv，所以不支持” |
| 特权空计划、组合点名或描述性名称 | 补齐明确点名、语义和规则；用 source_request_map 保留原场景 | “旧计划不完整，无法开始” |
| 共享／子目录生成器、priv CSV | 声明真实源码，保留指令矩阵，补齐注册入口及受影响消费者的回归 | “必须存在同名顶层 Python 文件” |
| 规则未进入公开索引 | 绑定固定原文的准确行段，标记待补标签，并使用 untagged_upstream 跟踪 | “没有规则索引，就没有规范” |
| 没有现成目标配置或免费模型 | 生成独立配置、模型及测试，区分模型自测与实际 DUT 结果 | “缺现成模型，不能生成测试” |

生成器接口和资产路径以固定 ACT 版本为准。新增的原生接口应遵守
[ACT 开发者指南][developer]，禁止改签名或验收条件来隐藏错误。

## 4. 需要更大验证基础设施的 Test Suite

这些类型也不是永久排除项，而是需要将额外工作明确纳入补全计划。

| 类型／示例 | 可以由工作流生成或补齐 | 仍可能需要的外部输入 |
| --- | --- | --- |
| `IOMMU` | 阅读独立规范，设计翻译/保护/队列用例，生成 DMA 激励、MMIO 驱动、模型与观察适配 | 目标接口、地址图、设备/上下文配置；实际目标连接 |
| `DM`、`DTM`、`Sdext` | 调试事务驱动、状态模型、halt/resume 测试及接口适配 | 实际调试连接与目标支持配置；不能用模型替代真实硬件测试 |
| `IMSIC`、`APLIC` | 中断/MSI 激励、配置驱动、路由模型与结果检查 | 目标拓扑、中断源和投递接口 |
| `Smaia`、`Ssaia`、`Sdtrig*` | 根据规范分解 CPU 侧行为及需要外部设施的子场景，分别补齐 | 仅针对实际依赖的投递/调试接口取证，不把整类功能阻塞 |
| 多 hart／内存模型场景 | 生成并发协调程序、允许结果集合判定和运行脚本 | 目标 hart 数、互连/存储模型及可观察结果 |
| `Zkt`、`Zvkt` 等时序要求 | 设计时序刺激、采样与对照分析，编写测量适配器 | 真实可解释的时序观测；功能签名不能证明时间无关 |
| 微架构内部覆盖 | 根据公开或用户提供的设计描述生成白盒观测与检查 | 内部接口、信号和设计约束；ISA 不能定义未公开的实现细节 |

独立规范通过运行配置 upstream.manual_root 选择固定 Git 仓库，来源可以是仓库内 .adoc/.md/.rst，
不强求位于 riscv-isa-manual 的 src/。若请求横跨多个规范仓库，先准备可追溯的固定输入并
明确各部分的来源；不能拿不相关的 CPU 规则填充设备规范缺口。

需要通用 ACT 框架增强时，AI 可以在独立副本生成补丁、最小复现和回归。该增强与 suite
资产分开保存和验证，不在正式副本偷偷改动公共执行环境。依赖尚未完成集成时，如实报告，
不能声称仅凭 suite 的 changes.patch 就已覆盖完整目标。

## 5. 允许限制或请求帮助的情况

- **商业工具许可**：Questa、VCS、Xcelium 等可以跳过相应商业验证；覆盖源码及其他可执行
  验证仍需完成。不得自动购买许可，也不能把免费编译器归入此类。
- **具体外部输入**：目标参数、规范歧义、访问授权或真实设备，必须列出精确问题、调查证据
  和受影响的子场景。AI 能实现的软件不能仅因上游缺失而转交用户。
- **请求范围尚不明确**：Test Suite 列中有组合名称、供应方名称、分组标题和待办描述。
  能从表格上下文及规范解析时自行解析；有歧义时问清范围。标题不是测试模块，但不能把
  名称不等于文件名当作架构功能不支持。

CLI 的 DUT 使用 [Test Suite 目录](test-suites.md) 中的文件安全标识，
启动时按目录快照校验；原始需求、原生入口及其对应范围写入 completion_plan。
这两个概念不能混淆。商业可选、实际外部阻塞和本轮尚未完成的工程任务应分别报告。
