# 提示词使用方法

[提示词.md](提示词.md) 是用户与协作 Agent 的长期操作协议。它不负责生成业务提示词，而是预先约定环境变量、UCAgent 认识、tmux 监督和干预策略、短指令、诊断方法和不可违反的修改边界。

## 首次使用

新会话开始时，先告诉 Agent 本次环境变量，例如：

```text
UCAGENT_HOME=~/FDocB/UCAgent
WORKFLOW_BUILDER_HOME=~/FDocB/UCAgent/examples/workflow_builder
BUSINESS_ROOT=~/FDocB/UCAgent_t/workspace_docx
WFB_WORKSPACE=~/FDocB/UCAgent_t/workspace_docx/workspace
TMUX_SESSION=ucagent_workflow_builder
```

然后给出：

```text
请完整阅读 docs/Usage/提示词.md，牢记其中的环境变量、短指令、监督策略、干预策略和修改边界。完成后建立认识。
```

Agent 应先确认路径、阅读 UCAgent 的关键入口和子工作流中心设计，再接受后续简短指令。

## 常用短指令

- `监督运行`：启动自动 loop TUI，按固定间隔观察，连续失败时定位原因。
- `干预运行`：关闭自动 loop，通过 MCP 获取角色和当前任务逐步完成。
- `继续监督`：保持现有策略，不重新启动、不清历史。
- `查看状态`：报告阶段、失败次数、最新工具调用和产物变化。
- `检查失败原因`：从 Checker、日志、引用、上下文和外部错误区分根因。
- `深度修理`：修改子工作流或母工作流中得到证据的问题并运行验证。
- `检查产物`：审查实际生成文件，不代替子工作流补产物。

短指令只在协议已经加载、环境变量已经约定后才有稳定含义。新 Agent 或压缩后丢失关键上下文时，应重新给出环境摘要和当前状态，而不是假设其保留上一个会话记忆。

## 监督与干预的切换

监督模式默认使用 Makefile 的 `--loop`。切换到干预模式前先安全停止当前 TUI，避免两个 Agent 同时处理一个阶段；随后使用 `RUN_LOOP_ARGS=` 启动。干预结束恢复监督时，也应先确认当前阶段和历史状态，不要创建第二个并发会话。

## 提示词使用边界

协议中的路径是变量，不应硬编码某个历史工作区。Agent 只能修改用户允许的子工作流或 `workflow_builder` 范围，不能擅自修改 UCAgent 核心。监督的目的是真实检验工作流，因此除干预模式的当前任务外，不得直接代写业务产物。

## 状态交接

长流程交接应至少记录：工作区、tmux session、运行策略、当前阶段、失败次数、最近证据、已修改文件、已跑测试和下一动作。这样即使发生上下文压缩，Agent 也不会反复从头读取全部文档。

## 首次加载确认模板

```text
已加载协议。当前 UCAGENT_HOME=...，WORKFLOW_BUILDER_HOME=...，
BUSINESS_ROOT=...，WFB_WORKSPACE=...，TMUX_SESSION=...。
我只修改允许范围；监督模式不代写子工作流产物；连续失败时先取证。
下一步建立 UCAgent 入口、母配置、中心设计和当前状态的初步认识。
```

用户应检查 Agent复述的路径，特别是 `BUSINESS_ROOT` 与 `WFB_WORKSPACE`。错一层会导致 Make从错误 sibling input 复制需求。

## 压缩后的恢复提示

```text
恢复协议上下文：继续使用已约定变量和监督策略。
当前阶段=<name>，失败次数=<n>，最近错误=<summary>，
已确认=<facts>，尚未确认=<hypotheses>，下一动作=<one action>。
不要重新全文读取全部文档；按当前错误读取直接相关文件。
```

若 Agent明显忘记固定边界，再读取协议相关章节，不必每次重载全部 800 行。

## 指令优先级和报告质量

最新用户指令优先；`停止运行` 立即停止；`继续监督` 不重启；`修理并重跑` 才包含修改和重新启动；`查看状态` 只读。组合指令按安全停止、分析修改、验证启动执行。

状态报告要区分事实与判断。“stage 3 失败 5 次、错误相同、mtime 未变”是事实；“Checker可能过严”是待验证判断。没有证据时不能直接宣称网络或模型问题。
