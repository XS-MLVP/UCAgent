# workflow 生成需求

请根据这里的需求生成一个 UCAgent 工作流。实际使用时，直接替换本文件内容即可。

## 目标

生成一个名为 `workflow` 的工作流，读取 `input/` 下的用户输入，在输出目录中生成结果。

## 输入约定

- 输入文件位于工作流运行目录的 `input/`。
- 本构建工作流的需求入口固定为 `../input/guide.md`。

## 输出约定

- 生成工作流写入 `output/workflow/`，也可以通过 `make OUT=<目录>` 覆盖输出根目录。
- 生成工作流必须包含 `README.md`、`docs/01快速启动.md`、完整用户文档、
  `requirements.txt`、`config.yaml`、`Makefile` 和必要的 `Guide_Doc/`。

## 验收

- 生成结果能通过静态检查。
- 文档说明输入、输出、运行命令和常见故障处理方式。

## 工具与 Checker 描述要求

需求编写者应尽量逐项说明期望的业务工具和 Checker。每个工具至少写清使用阶段、原始输入、输出字段或文件、核心处理规则、异常情况以及一个正常示例和边界示例；不要只写“生成工具”“检查结果”这类无法落地的名称。每个 Checker 至少写清检查对象、必须读取的结构化字段、通过条件、失败条件、错误证据和对应阶段。需求没有规定实现细节时，工作流必须在首阶段实现计划中主动补充调用链、算法或判定流程、错误传播、fixture、回归测试和扩展点，而且规划的详细程度必须高于本需求原文，不能简单改写用户描述。

工作流后续发现确有必要增加工具时可以新增，但必须同步更新 requirements manifest、实现计划、工具 spec、源码、配置注册、测试和 `docs/04开发者文档-tools.md`；新增 Checker 同理更新中心 workflow spec、fixture、测试和 `docs/05开发者文档-checkers.md`。不允许只在 `tools/` 或 `checkers/` 下留下未登记文件。
