
# AI 推理芯片 PE 核设计规格说明书

FP8 / FP4 块缩放矩阵乘加单元，面向功能验证与 PPA 探索。

| 项目 | 内容 |
|---|---|
| DUT 名称 | `npu_pe_core` |
| 综合、仿真和 PPA 顶层 | `npu_pe_core`，包含完整输出 tile 的计算与控制 |
| 默认验证规模 | `ARRAY_M=4`、`ARRAY_N=4`，输出 16 个 FP32 元素 |
| 输入格式 | FP4 E2M1；FP8 E4M3FN、E5M2 |

## 1. 合同边界与设计自由度

### 1.1 文档职责

| 文件 | 权威内容 |

“必须”“不得”和标为“强制”的内容构成验收要求。“参考”“建议”“可选扩展”不构成结构或数值门槛，不得从参考结构推导额外的内部信号、固定流水拍数或指定资源数量要求。

### 1.2 强制功能范围

- 计算一个 `ARRAY_M × ARRAY_N` 输出 tile；每次事务独立，从零开始归约 K 维。
- 支持 E2M1×E2M1、E4M3FN×E4M3FN、E5M2×E5M2、E4M3FN×E5M2、E5M2×E4M3FN 五种输入组合。
- 支持 E8M0 块缩放和 scale bypass；支持 `1 <= K <= 4096`，包括不满一拍和不满一个块的尾部。
- 输出 FP32；支持一个 tile 共享的 FP32 Bias，以及 Bypass、ReLU、ReLU6 后处理。
- 支持输入气泡、内部反压、输出反压、事务间格式切换和事务中复位取消。
- 实现可综合电路、独立 Python 可执行规格，以及在 Python reference 和 RTL 上复用的功能测试。
- 完成默认 4×4 配置的性能实测和 PPA 优化，保持所有候选的功能合同一致。

### 1.3 可选扩展

以下内容是后续扩展方向，不是本 case 的完成门槛：GELU / SiLU、FP16 / BF16 / FP8 / FP4 输出量化及 scale 生成、任意 FP32 per-tensor scale、FP4×FP8 混合宽度、额外舍入模式、外部残差矩阵 C、结构化稀疏、DFT / scan / BIST、FPGA 上板、门级后仿、大阵列和系统级精度评估。

扩展不能复用保留配置位改变本合同，不能取代五种必选格式、FP32 精度或基准 workload。需要改变公共接口或数值语义的扩展应作为独立 case 评估。

### 1.4 允许自由探索的实现

在外部行为满足合同的前提下，可以自行选择并改变：

- 脉动、广播、分层归约、时分复用或混合数据通路；OS / WS 等内部数据流。
- 物理计算单元数量、K 维物理并行度、乘法器是否共享、是否采用位分割。
- 内部整数 / 定点表示、精确累加宽度、加法树、进位保存、分段累加和寄存器重定时。
- 流水级数、输入缓存、双缓冲、预取和块处理重叠；允许通过 `data_ready` 插入等待。
- 操作数隔离、合法的零值跳过、寄存器使能与门控策略。

4×4 是逻辑输出 tile，不强制存在 16 个物理 PE。32-bit 行/列输入字中的 4 个 FP8 或 8 个 FP4 元素是传输宽度，不强制每拍完成相同数量的物理乘加。允许增加延迟或调整资源使用进行候选实验，候选是否保留按性能合同和本次运行的验收策略决定。

接口、输入编码、数值结果、特殊值语义和 workload 不属于优化变量。不能通过缩小 K 范围、丢弃 subnormal、降低累加精度、假定输入稀疏或修改测试来获得改善。

## 2. 参数与数学任务

### 2.1 参数范围

| 参数 / 配置 | 合同 |
|---|---|
| `ARRAY_M` | 整数，1..8，默认 4，输出行数 |
| `ARRAY_N` | 整数，1..8，默认 4，输出列数 |
| `K_DIM` | 每个事务锁存的整数，1..4096 |
| K-block | 固定 32 个元素，不是优化参数 |
| 每行 A / 每列 B 传输字 | 固定 32 bit |
| 每拍逻辑 K 元素数 `L` | FP8 为 4，FP4 为 8 |

同一份源码必须支持上述阵列参数范围。至少以 1×1、2×3、4×4 和 8×8 配置运行参数化 smoke 回归；完整功能与 PPA 验收使用 4×4。大于 8 的阵列只作为扩展，不要求通过修改参数证明 256×256 的物理实现可行性。

内部可以增加静态实现参数，但必须在架构和版本证据中记录。不能改变上述公共端口的宽度公式或合法输入集合。

### 2.2 块缩放矩阵乘加

对输出元素 `(i,j)`，理想实数表达式为：

```text
sum(i,j) = sum over k=0..K-1 of
           decode(A[i,k]) * decode(B[k,j])
           * scale(SA[i,floor(k/32)]) * scale(SB[floor(k/32),j])
D(i,j) = activation(sum(i,j) + bias)
```

`SA` 的逻辑形状是 `ARRAY_M × ceil(K/32)`；`SB` 的形状是 `ceil(K/32) × ARRAY_N`。同一事务中的 A 格式、B 格式、Bias、激活和 scale 模式均固定。

实数表达式说明数学意图；逐 bit 验收必须使用本文第 4 节的舍入顺序。主机负责上层矩阵 tiling 和量化，DUT 不负责访存、量化器或整个模型调度。

## 3. 数值编码

### 3.1 E4M3FN

一个 byte 的 bit 7 为符号 `s`，bits `[6:3]` 为指数 `e`，bits `[2:0]` 为尾数 `m`。

| 编码条件 | 精确数值 |
|---|---|
| `e=0, m=0` | 有符号零 |
| `e=0, m!=0` | `(-1)^s * m * 2^-9` |
| `1<=e<=14`，或 `e=15, m<=6` | `(-1)^s * (8+m) * 2^(e-10)` |
| `e=15, m=7` | NaN，正负编码均视为 NaN |

最大有限值为 `0x7e = 448`；最小正规值为 `0x08 = 2^-6`；最小 subnormal 为 `0x01 = 2^-9`。该格式没有 Inf，`e=15` 仍包含有限值。`0x38 = +1`、`0xb8 = -1`、`0x7f` 和 `0xff` 是 NaN。

### 3.2 E5M2

一个 byte 的 bit 7 为符号 `s`，bits `[6:2]` 为指数 `e`，bits `[1:0]` 为尾数 `m`。

| 编码条件 | 精确数值 |
|---|---|
| `e=0, m=0` | 有符号零 |
| `e=0, m!=0` | `(-1)^s * m * 2^-16` |
| `1<=e<=30` | `(-1)^s * (4+m) * 2^(e-17)` |
| `e=31, m=0` | 有符号 Inf |
| `e=31, m!=0` | NaN |

最大有限值为 `0x7b = 57344`；最小正规值为 `0x04 = 2^-14`；最小 subnormal 为 `0x01 = 2^-16`。`0x3c = +1`、`0xbc = -1`、`0x7c = +Inf`、`0xfc = -Inf`。转出到低精度浮点时需要舍入，不能把通用格式转换等同于尾数截断。

### 3.3 E2M1

一个 nibble 的 bit 3 为符号 `s`，bits `[2:1]` 为指数 `e`，bit 0 为尾数 `m`。

| 正编码 | 值 | 负编码 | 值 |
|---|---:|---|---:|
| `0x0` | +0 | `0x8` | -0 |
| `0x1` | +0.5 | `0x9` | -0.5 |
| `0x2` | +1 | `0xa` | -1 |
| `0x3` | +1.5 | `0xb` | -1.5 |
| `0x4` | +2 | `0xc` | -2 |
| `0x5` | +3 | `0xd` | -3 |
| `0x6` | +4 | `0xe` | -4 |
| `0x7` | +6 | `0xf` | -6 |

`e=0` 时数值为 `(-1)^s * m / 2`；`1<=e<=3` 时数值为 `(-1)^s * (2+m) * 2^(e-2)`。共有 16 个编码、15 个不同实数值，无 NaN、无 Inf；最大值 6，最小非零值 0.5。

### 3.4 E8M0 与 scale bypass

| 编码 | 含义 |
|---|---|
| `0x00..0xfe` | 正有限值 `2^(unsigned(code)-127)` |
| `0x7f` | 1.0 |
| `0xff` | NaN |

E8M0 没有零或 Inf 编码。`0x00` 是 `2^-127`，不是零；`0xff` 是 NaN，不能作为零块标志。两个有限 scale 的无偏乘积指数为：

```text
scale_shift = int(sa) + int(sb) - 254    # range: -254..254
scale_a * scale_b = 2^scale_shift
```

scale 相乘不需要通用尾数乘法器，但指数运算必须有足够的有符号位宽，应用 scale 时仍须处理 FP32 舍入、溢出和下溢。不能用 8-bit 加法回绕，也不能把带偏置指数直接当作移位量。

scale bypass 时，两个 scale 都按精确的 1 处理，忽略 scale 输入的所有编码，包括 `0xff`。块边界和舍入顺序仍与开启缩放时相同。

### 3.5 格式组合

配置编码 `00=E2M1`、`01=E4M3FN`、`10=E5M2`、`11=保留`。仅本文第 1.2 节的五种组合有效，FP4 与 FP8 不能在一个事务中混合。E4M3FN 和 E5M2 的混合组合两个方向都必须实现，不允许按相同 byte 编码解释两种格式。

## 4. 确定性数值运算合同

### 4.1 FP32 舍入原语

`R32(x)` 表示把精确值舍入为 FP32，固定采用 round-to-nearest, ties-to-even（RNE），保留 gradual underflow，不启用 FTZ / DAZ。

- 有限溢出按 IEEE 754 RNE 得到相应符号的 Inf，不饱和到输入格式的最大值。
- 正 / 负 Inf 保持其符号，分别编码为 `0x7f800000` / `0xff800000`。
- subnormal 结果正常编码；负的非零精确值下溢为零时保留负零。
- 精确零结果统一为 `0x00000000`，包括正负抵消和全零块。
- 所有 NaN 结果规范化为 quiet NaN `0x7fc00000`，不保留输入 payload 或符号。

`ADD32(a,b)` 表示对两个 FP32 值作精确加法再执行 `R32`，包括上述零与 NaN 规则。普通有限非零结果按 IEEE 754 RNE 判定；不允许依赖宿主语言的隐式精度或默认 NaN 表示。

### 4.2 每个 K-block 的归约

对块 `q`，有效索引范围为 `32q <= k < min(32q+32,K)`：

1. 精确解码有效 A、B 元素，精确计算乘积。
2. 在块内对乘积作精确求和 `Uq`，不在 lane、拍或树节点舍入。
3. 若开启缩放，计算精确的 `Uq * 2^(sa+sb-254)`；bypass 时保持 `Uq`。
4. 执行一次 `R32` 得到 FP32 块贡献 `Tq`。

有效元素出现 NaN、有效乘法出现 `Inf*0`，或同一块的乘积同时含正 Inf 与负 Inf 时，该块贡献为 canonical NaN。开启缩放时，任一适用于该输出元素的 scale 为 `0xff`，该块贡献也为 canonical NaN，即使块内元素全为零。

若没有 NaN 条件且存在 Inf 乘积，则块贡献为对应符号的 Inf。否则使用精确有限归约。E8M0 的有限 scale 再小也不等于零。

未使用的尾部 lane 不属于运算集合，其 NaN / Inf 编码不传播；有效 lane 的零值不能遮蔽 NaN scale 或 `0*Inf`。

### 4.3 跨块累加与后处理

对每个输出元素独立执行：

```text
acc = FP32(+0)
for q in increasing block order:
    acc = ADD32(acc, Tq)
z = ADD32(acc, bias)
result = activation(z)
```

跨块每步均舍入到 FP32；Bias 只加一次。`Inf + (-Inf)` 和任何 NaN 加法产生 canonical NaN。允许并行准备块贡献，但不能以会改变结果的方式重排、融合或删除这些舍入点。scale bypass 也不允许把所有块改成一次总归约。

本合同定义的是“块内精确、块间 FP32”的点积，不声称等同于逐元素 FP32 FMA 或任意外部库的矩阵乘法。内部整数位宽只要能证明覆盖全部有限输入、scale 和 K 范围即可；不强制使用浮点寄存器或通用浮点加法器。

### 4.4 激活函数

| 模式 | FP32 行为 |
|---|---|
| Bypass | 输出 `z` |
| ReLU | NaN 保持 canonical NaN；`z<=0` 输出 +0；其余输出 `z` |
| ReLU6 | NaN 保持 canonical NaN；`z<=0` 输出 +0；`z>=6` 输出 `0x40c00000`；其余输出 `z` |

因此 ReLU 的 `+Inf` 保持 `+Inf`，ReLU6 的 `+Inf` 变成 6，两者的 `-Inf` 都变成 +0。比较和限幅不能把 NaN 当作普通负数丢弃。Bias 可以是任意 FP32 编码，其 NaN 同样规范化。

以下向量的 expected 必须从本节规则构造，不能读取 DUT 结果反填。

| 场景 | 条件 | 每个受影响输出元素的 FP32 expected |
|---|---|---|
| FP4 单块 | K=32，所有有效 A/B=1，SA/SB=`0x7f`，bias=0，Bypass | 32，`0x42000000` |

## 5. 参考微架构与探索方向

本节全部为实现参考。生成架构时应写清选择理由和待验证假设，不能把参考选型转成额外的强制功能。

### 5.1 参考数据通路

```text
atomic input packet
  -> buffer / unpack / classify
  -> exact low-precision products
  -> exact block reduction + scale exponent adjustment
  -> RNE to FP32 block contribution
  -> ordered FP32 block accumulation
  -> FP32 bias + activation
  -> row result buffer + ready/valid output
```

可以先实现容易验证的共享计算资源版本，再探索更多并行 lane、更宽归约树、块缓冲与流水。也可以直接采用并行阵列；不要求某个指定结构成为 base。

### 5.2 脉动互联与 skew

一种参考结构是每个逻辑输出元素映射到一个 PE，A 沿行传播，B 沿列传播。若每个相邻 PE 的有效传输延迟相同，可对行 i 的 A 和列 j 的 B 做对应偏斜，使同一个 k 在 `(i,j)` 配对。

外部输入无需 skew；内部负责数据、scale、valid、块编号和尾 lane 信息的对齐。气泡或停顿时，必须同时推进或保存相关元数据，不能只延迟数据字。固定的 `i+j` 拍到达关系仅适用于特定无停顿结构，不能成为所有实现的验收条件。

广播或共享计算实现可以完全不使用 skew 链。正确性观察点是每个输出元素所消费的有序 K 元素和块 scale，不要求测试访问固定内部层次或信号名。

### 5.3 FP4 / FP8 乘法复用

FP8 尾数有效位最多 4 bit，FP4 尾数有效位最多 2 bit。可以比较专用小乘法器、查表、逻辑展开与可分割乘法阵列。直接把两个 2-bit 操作数拼起来做一次普通 4×4 乘法会产生交叉项，不能自然得到两个独立乘积。

是否复用及复用粒度由综合面积、关键路径和活动功耗决定。不预设“FP4 面积增量为零”或“指数通路也可直接对半分割”。

### 5.4 累加与延迟规格化

块内精确和可以用整数超累加器、分段指数桶、进位保存或等价表示实现，并在块边界统一规格化。由于块内没有规定浮点舍入点，允许改变归约树顺序。

块间必须保留第 4.3 节的 FP32 舍入结果。普通 FP32 的 `local_acc += product` 不自动等价于精确块和；同样，把所有块保留额外精度到事务末再舍入也不等价。优化必须覆盖严重抵消、半 ULP、小项累积和溢出后异号累加等反例。

### 5.5 低功耗与稀疏

可以检测真实零元素并隔离操作数，或在已证明该输出的整个块贡献是零后省略无效计算。仍需消费完整逻辑输入流，维护 K 计数并保留数值异常语义。

零块跳过不能使用 `scale=0xff`，也不能在检查 NaN / Inf 之前将所有 `0*x` 简化为零。丢弃小项、缩窄位宽或启用近似运算只有在证明全输入域逐 bit 等价时才是有效优化。

建议优先使用工具链可综合的寄存器使能和操作数隔离；采用工艺 ICG、RAM / DSP 宏时，应有可用的仿真与综合模型，并在所有可比版本中保持相同库与计量范围。不得将模块变成无代价黑盒。

## 6. 工艺、算力与物理参考

### 6.1 参考目标

| 参考项 | 数值 / 意图 | 验收解释 |
|---|---|---|
| 功能仿真时钟 | 10 ns | 固定时基；不证明电路可达 100 MHz |
| ASIC 探索方向 | 16nm、1 GHz | 只有对应库和实际时序证据才能宣称达到 |
| 16 个物理 PE 的面积预算 | 每个 0.018 mm²，总计 0.288 mm² | 架构预算参考，不是跨工艺硬门槛 |
| 4×4 功耗预算 | 48 mW @1 GHz | 需匹配电压、库、活动率与测量范围，不能直接当作结果 |

这些数值不设置 `hard_requirement: true`，也不能用来预填 PPA 实测值。仿真周期设为 1 ns 或 10 ns 不能替代 STA，也不能单凭时钟周期推断仿真墙钟速度。

### 6.2 理论带宽上限

在每拍接受一个输入包、所有逻辑输出均并行计算、无气泡且不计启动 / 结束开销时：

```text
useful MAC/cycle = ARRAY_M * ARRAY_N * L
nominal operations/second = 2 * useful MAC/cycle * frequency_hz
```

4×4、FP8 时上限为 64 MAC/cycle，FP4 时为 128 MAC/cycle。乘加按 2 次运算计，在实际可达 1 GHz 的前提下分别为 128 和 256 GFLOP/s。它们是传输与并行度参考，不能替代实测吞吐，也不强制 FP4 的端到端性能恰为 FP8 的两倍。

### 6.3 物理实现注意事项

若采用脉动互联，可探索邻接布局和局部时钟树；FPGA 可比较 LUT 与 DSP 实现。面积、电压、布线、时钟树、IR drop 与大阵列扩展需相应的后端证据，4×4 功能通过不等于产品规模已验证。

STA 必须覆盖真实寄存器和组合路径。scale 更新较少不构成 multicycle 或 false-path 的依据；只有接收端确实延后采样且控制协议保证该行为时才可使用合法例外，并解释 setup / hold 配套约束。不能屏蔽关键路径制造频率提升。
