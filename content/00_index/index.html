    UCAgent 文档¶

    UCAgent 是面向数字电路单元测试的 AI 验证代理。它读取 DUT 和验证需求，按阶段生成文档、测试代码和覆盖率模型，运行测试并保留可复核的报告。每个阶段都由确定性 Checker 验收，必要时可以人工介入或让外部 Code Agent 通过 MCP 调用工具。

    先跑通一次¶

    第一次使用建议按下面顺序阅读：

    1. 前置依赖安装：安装 UCAgent、picker 和可选的 Code Agent。
    2. 运行模式总览：选择普通模式、MCP 接入或 Master 模式。
    3. 选择一条上手路径：普通模式使用 LangChain 直连模型；MCP 接入使用 opencode 等外部 Code Agent。
    4. 结果分析与流程总结：了解工作区和验证产物。

    需要集中管理多个任务时，再阅读 Master 模式。

    UCAgent 的边界¶

    • picker 负责把 RTL 导出为可由 Python 驱动的 DUT 包；UCAgent 负责验证流程和产物管理。
    • UCAgent 不替用户决定 DUT 规格。README、RTL 和其他参考文件应先准备好，测试失败也需要结合规格判断是测试问题还是 DUT 缺陷。
    • 不同模式共用工作流和 Checker，但模型连接方式、进程数量和交互入口不同。

    文档导航¶

    本文档组织为以下几个部分：

    开始使用¶

    1. 前置依赖安装：UCAgent 环境部署、模型配置基础准备
    2. UCAgent 运行模式总览：普通模式与 Master 模式对比，后端选择与交互界面入口
    3. 普通模式：DUT 准备、模型配置与终端（TUI）直连验证
    4. MCP 接入：以 opencode 为例接入外部 Code Agent
    5. Master 模式：面向人机协同可视化操作与多任务管理
    6. 任务、工作区和工作流：跑通流程后理解输入、产物和验收
    7. 结果分析 & 通用流程总结：统一结果解读、通用操作规范

    使用导读：先用普通模式或 MCP 模式完成一个任务，再根据需要启用 Master、多实例或批处理。命令中的 <workspace>、<DUT> 等是需要替换的示意值，不要原样输入尖括号。配置文件中的 {WORKSPACE}、{DUT}、{OUT} 则是 UCAgent 模板变量，{OUT} 默认是 unity_test。
