# 如何检查观察点精度与未证明义务

## 何时使用、准备什么

新增 DUT、定义功能点、写观察点或复核“全绿”时使用，尤其是内部类型宽于导出端口、字段
被裁剪、消费者还需要更多位的情况。输入为语义类型/宽度、生成端口清单、producer/consumer
实际赋值、规格中的功能点与未证明范围。

本方法回答哪些字段的正确性尚未建立，以及什么证据允许关闭；不替代合法激励或 oracle。

## 三个来源各管一段

| 来源 | 能提供什么 | 不能替代什么 |
|---|---|---|
| ISA / 总线协议 / 接口合同 | 必须发生的语义，独立 oracle 的依据 | 不能从实现倒推这份要求 |
| 设计源码（如 Chisel/Scala） | 意图、状态、读写关系和分支线索 | “实现如此”不是正确答案 |
| 生成 RTL / Picker 端口 | 当前能驱动、能观察的物理面 | 端口形状不是语义，源码断言也未必保留 |

生成过程可能丢弃 verification layer：只读生成 RTL 会漏掉设计者认为必须成立的性质，
只读源码又可能把已裁剪字段当成可观察。逐项核对断言是否真正存在并启用，不只数源码 assert。

## 怎么做

1. **每字段三问。** 规格是否要求它被驱动/观察？源码谁写谁读？生成端口是否存在？第三问
   为否时区分有理由的裁剪与未驱动/未接入候选，不能跳过或用“端口就这样”关闭。
2. **筛选门与关闭门分开。** 筛选时只要正确性尚未证明就留下，不要求先观察到它错；关闭时
   默认不放行，必须有消费者合同、独立性质、结构证明或动态反例处置。偏向保留是风险姿态，
   不是把所有线索都升级为已确认缺陷。
3. **系统扫描内部宽/端口窄。** 列 PC/GPA、地址高位、异常元数据、指针、理由位、调试字段
   的语义宽度与导出宽度。自动形状差集交给脚本；差集只分诊，不能代替语义判定。
4. **从消费者倒推所需精度。** 找实际赋值、零扩展和重拼接路径。消费者需要而端口装不下时，
   本层正确性未建立，不能把较窄端口写成需求来消掉缺口。
5. **逐项分类。** 采用下表，不用“未验证”冒充“不适用”。
6. **每个留项三件事。** 写关闭条件、承接方及其当前状态、对结论的影响。缺任一项就补全，
   否则清单会变成无法行动的噪声。
7. **边界变化触发重查。** 让字段存在性/宽度自检在参数、配置、基线变化时失败并提示复核；
   已判缺失的字段重新出现也要重新判定，不静默沿用旧 PASS。
8. **拒绝三类关闭理由。** “端口就这么多位”“RTL 就这么实现”“别的工程也这样”只是线索，
   不能单独关闭。

| 分类 | 处置 |
|---|---|
| 已证明消费者不需要该位 | 附证明、配置条件后关闭 |
| 消费者需要但端口装不下 | 保留交接面限制/候选，确认承接层 |
| 无端口且无合法观察路径 | 未验证，记录导出需求或上层承接 |
| 源码要读而生成端口没有 | 缺陷候选；区分生产者未驱动和被裁剪 |
| 仅怀疑、无证据 | 做有界探针，不称已确认或已排除 |

## 产出

在设计规格的观察/范围章节维护同一套 ID，关联 `Guide_Doc/ut-contracts.md` 中的要求：

| id | 字段/行为 | 内部语义宽度 | 观察端口 | 消费者需要 | 判断 | 关闭条件 | 承接 | 影响 |
|---|---|---|---|---|---|---|---|---|
| 稳定 ID | PC/地址/异常等 | 类型或位数 | 实际导出字段 | 消费者合同 | 留下/关闭/承接 | 具体证据 | 层与状态 | 不能下的结论 |

再给源码写者/读者的文件位置与实际端口清单位置，避免责任矩阵、残余和观察清单各写一份。

## 如何验收

- 对内部宽而端口窄的历史漏项，设计期就能留下“正确性未建立”，无需等动态症状。
- 抽查源码读而端口无的字段，能区分未驱动与裁剪，给出不同处置。
- 关闭项有独立依据；留下项有可执行关闭条件、承接方、影响。
- 构造器和比较器不静默补齐缺失位；未验证不被称为不适用或确认缺陷。
