# 如何划分行为等价类和关键组合

## 何时使用、准备什么

功能点只有指令清单、单路径用例或“覆盖率很高”时使用。输入是
[DUT 合同与合法域](../requirements-boundary/SKILL.md)、模块行为清单、状态历史和错误模型。

**行为族、功能 ID、场景、参数实例是不同层次。** 行为族可关联多个要求；场景明确输入、
前态和结果；参数只有改变可观察行为或检错能力时才形成独立等价类。旧 ID 全部归类不等于
场景矩阵已建立。

## 怎么做

1. **建立来源到 DUT 的映射。** 每个能到达本层的指令/上游事务族，映射到字段、编码、模式
   和历史条件，分别判本层、出域（谁承接）、未证明。只有合同保证观察和状态转移相同才能
   合并；字段同值而历史不同不能自动等价，也不能因没有用例就假定某族不存在。
2. **按模块挑维度。** 检查操作、身份/年龄、地址/粒度、权限/属性、资源状态、取消/复位、
   并发；再显式考虑响应结果域，如完成、故障、重放、refill、tag 错误、翻译 miss。按当前
   合同选域，不给没有错误端口的 DUT 强加总线 fault 列；特定架构扩展不是所有模块必填项。
3. **构造区分性样本。** 写正确行为和代表性错误行为各会输出什么。不只在刺激侧造非法输入，
   还应在合同适用时，对同一合法刺激改变响应域并检查消费侧结果。若两种算法仍同答，就换
   边界、数据或历史，不能靠用例名字声称检查了优先级。
4. **分层安排组合。** 单维之后定向补高风险交叉、边界、历史序列，并说明理由。pairwise 和
   约束随机只补大空间，不能保证高维交互或时序性质；有限矩阵逐格处置，不留空白。
5. **检查时序。** 分开同拍竞争、背压多拍、先错后对、失效/refill 交错、取消后续接、ID/槽位
   回绕；只有合同允许的历史才可作为功能反例。
6. **把反例回填到分类。** 同键异阶段、陈旧状态、权限作用域、编码别名或新增结果域出现时，
   解释原来为什么错并类；同步来源映射、矩阵与用例，不只加孤立测试。
7. **一致性检查脚本化。** 在 coverage 实现或 tests 自检中检查类别/结果域没有漏行、pass/fail
   有真实节点、gap 有缺什么和怎么补。规格仍是正文里的同一份合同，不另起运行前计划 JSON；
   自动检查通过只证明账目一致。

## 产出

在验证规格正文保留两张关联的表，要求/场景 ID 按 `Guide_Doc/ut-contracts.md`：

| 类/组合 ID | 合法前提与历史 | 合并/拆分依据 | 正确/错误差异 | 断言/nodeid | 状态 |
|---|---|---|---|---|---|
| 稳定标识 | 输入与前态构造 | 当前合同 | 可检查的区分点 | 实际比较位置 | 结果或残余 |

类别 × 结果域矩阵每格为 `pass` / `fail` / `gap` / `na` / `out-of-domain`。pass/fail 附同轮
run/nodeid，gap 写缺项与补法，出域项写承接层。尚未展开的大空间单独说明抽样策略和残余。

每场景还要有独立预期、禁止副作用、完成义务和必要交叉。来源未确认、前态未到达、观察
缺失、检查被首错挡住、没有用例分别记原因；不能统称未覆盖，更不能从族级 PASS 反推每个
场景都 checked。允许新增尚无旧 ID 的候选行为和 gap。

## 如何验收

- 来源没有静默遗漏或“其他”兜底；不能把“没测”写成出域。
- 对具有多结果域义务的类别，实际观察并检查错误/替代响应，不能只有干净完成。
- 优先级或同时性样本在反转规则时能产生可检查差异。
- 矩阵条目能追到真实检查或具体缺口，不仅关联 bin 或 sample。
- 结论仅覆盖已声明的类、交叉和实际运行，不声称字面穷举全部状态。
