
# repo_byte_increment

`repo_byte_increment` 是仓库模块开发工作流（`repo-module-tdd`）的最小演示任务：优化已有 Git 仓库源码快照中 `rtl/unit.v` 内的 `Unit` 模块。基线公开接口为无符号 8 位输入 `a` 与输出 `y`，必需行为是 `y = (a + 1) mod 256`。

## 必需行为

- 每个被接受的逻辑请求按顺序产生一个自增字节；`255` 必须回绕到 `0`。
- 工作负载至少覆盖输入 `0、1、127、128、254、255` 以及确定性的混合序列。
- 全部 DUT 激励与观测只使用 interface.yaml 声明的公开顶层引脚。
- 仓库只提供目标模块及其源码依赖；独立构建并测试本单元，不构建完整系统。
- 修改范围限于 `rtl/*.v`；基线没有外部源码依赖。

## 探索与约束

- 接口允许演进，前提是逻辑行为保持不变并如实记录调用方影响；必要的硬件协议或位宽适配必须包含在被测单元内。
- 内部进位架构、流水线结构与文件划分是参考选择；建议每个独立功能使用独立文件。
- 顺序化候选必须在 interface.yaml 中完整声明复位与握手协议。
- 顺序化候选与 PPA 测量使用 10 ns 时钟约束；逻辑延迟不超过 10 个周期，吞吐不低于每周期 0.1 个事务，每个工作负载场景须在 1000 个周期内完成。
- 在逻辑输入与到达时间不变的前提下，对照原始模块报告实测面积、时序与功耗。
