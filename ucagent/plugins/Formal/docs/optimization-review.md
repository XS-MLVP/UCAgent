
# Formal 优化评审：工程实测、已知问题与下一步方案

## 1. 评审目的与边界

本文记录从 Adder 到用户提供的 e203_biu 工程的实际观察，供独立评审模型检查当前实现与下一步设计。**本文不是任务的验证通过报告，也不将提案描述为已实现功能。**

约束：功能仅放在 Formal 插件；不修改原有 RunSkillScript、阶段生命周期或其他框架流程；不修改用户 RTL 使结果变绿；不加入模块名称、端口名称或特定运算的专属判断。data Skill 复用现有执行路径，不维护第二套工具系统。

不提交生成任务、用户上传的 RTL/README、模型完整转录、原始波形或本机配置。下述统计来自本次会话的固定任务与只读审计，原始运行产物在运行主机保留，不保证读者可从 GitHub 访问它们。对应问题由通用临时工作区回归覆盖；端到端数字不是可重复的严格性能基准。

## 2. 目前已经实现的能力

- RunFormal：按属性隔离尝试、公平队列、首轮预算、累计分析阈值、显式 retry/defer、取消与持久化证据。首轮默认约300秒，首次分析阈值是累计约1200秒，**不是300秒再加1200秒**。暂缓仍为 UNPROVEN。
- ext/formal/data：inspect/prepare/update，经原有 RunSkillScript 执行；Skill 关闭时普通文件工具维护同一规范数据，验收标准相同。
- 实际 RTL 的有效参数与端口展开：默认值来自声明，显式覆盖后重算派生参数，保留零值、位宽和符号；不从说明文字猜默认值。
- 统一编译上下文：plain filelist.txt 选择顺序源文件，宏/条件编译共享一个预处理单元；字面量本地 include 限定在 DUT 树内。解析器与生成 FormalMC Tcl 使用相同顺序及包含目录。此能力不是完整 SV 工程构建系统，不支持任意 filelist flags 或外部依赖。
- 首次失败分析维护规格关系与有界整数参考表达式，计算绑定精确的当前证据信号；Bug 阶段复制已核验 FA 数据，不能重新编造一份规格或数值。表达式算对不证明它符合规格。
- 原始输入/最后保存采样、X/Z、位宽、时间上下文及日志/反例哈希；机器 Bug 描述限定当前反例或静态检查，人工根因/影响范围单独标记。
- 总结直接派生机器统计、Bug 表、规划排除项及实际 CK/SVA 表；人工语义仍需审阅。
- 无 Skill 路径修改参考表达式时，先核验原派生结果，再原子刷新合法作者请求；prepare 与最终检查共享该核验，避免队列显示完成却无法推进。

## 3. 实测结果与正确解读

| Adder 轮次 | 启动至正式 Exit | 工具调用 | 观察 |
| --- | ---: | ---: | --- |
| 初始版本 | 57分21秒 | 210 | 脚本/数据/流程重复操作多 |
| data Skill 轮次 | 27分35秒 | 98 | 9阶段一次通过，但人工数值错误仍存在 |
| 参数绑定与类型契约问题暴露轮次 | 42分17秒 | 157 | 参数编译失败和错误恢复明显 |
| 参数/契约重构轮次 | 22分04秒 | 104 | 参数默认值正常，人工 expected 仍有错误 |
| 参考计算轮次 | 33分24秒 | 90 | 计算正确、交互较少，人工范围推断错误 |
| 分析复用轮次 | 28分03秒 | 94 | 7项计算只在首次 FA 提交，Bug 不重算；其他数据定位成本抵消调用收益 |

用户以工具调用、重复分析、结论可靠性为主，时间仅参考。相同 RTL、后端与 seed 不代表相同模型输出或属性集；跨轮目标不同，不能把总耗时变化全归因于代码。旧轮监控曾含转录 API-request 副本，旧指标沿用固定运行审计口径；e203_biu 最终统计只计真实 assistant tool_use 并按 ID 去重，不与含副本中间计数混用。

e203_biu 正式任务约12小时02分，去重748次调用，其中 Bash328、RunFormal187、RunSkillScript39；共23批：11准备 ERROR、4 CANCELLED、4 COMPLETED、4 AWAITING_REVIEW。最终76个CK含26 Assume、37断言、13 Cover；结果15 PROVEN、17 TRIVIALLY_TRUE、12 COVER_REACHED、6 UNPROVEN（全部暂缓），0当前反例、0已核验 RTL Bug。

6项缺口分别是命令进展、outstanding、分流 onehot、响应聚合、LSU 活性、错误响应 Cover。最终输入和44项已判定证据引用一致性通过，不等于整个规范正确或环境合理。用户附件最终保持原样。首次任务准备曾因本地附加配置覆盖系统提示而重启，保留为独立准备失败；不归因于 RTL，也不隐瞒该成本。

## 4. 已确认问题与风险

| 问题 | 本轮证据 | 不能得出的结论 |
| --- | --- | --- |
| SVA 错误发现晚 | 长括号表达式、非法时序组合、未声明白盒信号、32/192位错误比较进入工具后才暴露，11批准备失败 | 原始 RTL 有11个 Bug |
| 多周期证据不足 | 大量手写 trace 解析、列信号、反复找实例和bundle顺序，Bash328次 | 最后样本足以解释事务归属 |
| 假设驱动的伪通过风险 | 两次加入环境后所有断言判定通过但13 Cover全不可达；模型后来重新调整 | 全部断言通过就说明 DUT 正确 |
| 最终环境限制过强 | FIO 响应绑定同拍命令，其他目标绑定前一拍；保持valid的每拍仍触发，而非任意pending历史 | 覆盖所有合法响应延迟/背压 |
| 总结与实际假设矛盾 | 总结称未添加目标最终响应公平性假设，实际有相关 s_eventually Assume，部分包含 DUT ready | 活性结论不依赖公平性前提 |
| 修复反馈被无关目标阻挡 | 单条聚合修复后整体新批从头排队，前序慢属性反复占满首轮预算 | 旧 Pass 可直接复用到新输入 |
| REVIEW 处理不及时 | 就绪目标长时间未处置，后续才批量 defer/retry；多次取消/改输入重新搜索 | 无反例即引擎容量问题、可以忽略目标 |
| 人工推断仍错误 | Adder 影响段把单例推广为所有溢出输入；预算写成300+1200=1500秒 | 标记“人工”就代表内容正确 |
| 数据定位/配置接口不足 | 重复打印 FG/FC/CK、查字段；extra_config 无 Skill 更新路径，模型转为原生编辑/探测私有命令 | 所有额外调用都不可避免 |

公平性与假设需特别审查：Assume 引用 DUT 输出并非一律非法，例如外部响应依赖命令；关键是是否把 DUT 负责保证的响应/接收性质放进环境前提。Cover 可达仅证明某些场景有轨迹，不能证明环境没有排除其他合法行为。固定优先与公平仲裁也不能混为一谈。

## 5. 下一步提案：尚未实现，等待 Review

### P0：单条/多条属性诊断 Skill 与共享后端

拟议新增 ext/formal/prove，脚本经 RunSkillScript 调用现有 FormalExecution；RunFormal 提供等价选择能力供 Skill 禁用路径使用。不是新执行器。

- 输入为精确完整属性名列表；可先列当前有效 inventory，未知/重复/错误类型一次诊断。
- 只选择 Assert/Cover，保留当前完整 Assume 环境；输入快照与指纹仍覆盖 RTL、全部属性、假设和配置。
- 定向运行使用独立结果指针与 scope=selected；不覆盖 full 运行的验收指针。完整属性清单仍保留，未选项标 not executed，而非 Pass。
- 分开 selected_complete 与 full_complete，定向成功不得让 Check/Complete 错误放行整个目标集。
- 第一版不合并跨批次 Pass，不承诺 solver continuation。修复反馈后执行完整回归。
- 新完整批可优先排列变更/此前失败属性，但仍公平运行其他目标；输入或 Assume 改动必须使受影响证据失效。

验收：一条失败属性可定向复验；慢目标不阻挡所选其他目标；有覆盖缺口/过期指纹/未选目标时不能完整验收；取消与证据身份不混入另一个运行。

### P0：提交与生成阶段的 SVA 预检

在 data Skill 批量 body 更新和完整 Checker/Wrapper 生成处采用标准解析器，禁止自动改写表达式来消除错误。

- 语法、未声明信号及无效白盒连接为阻塞诊断；映射到精确 CK 与原始位置，避免生成行号级联错误。
- 一次返回有界的全部诊断；数据/生成物原子发布，失败不覆盖已接受产物。
- 可疑位宽比较返回两侧有效类型、宽度和显式转换位置；不能把所有合法零扩展/截断都误判非法。
- 必须在与 FormalMC 一致的预处理、参数、源顺序、时钟上下文下检查。解析器通过不替代实际工具兼容性和证明。

验收：括号、时序 and/逻辑 &&混用、缺失白盒、跨模块同名、合法/可疑宽度、宏条件端口、错误文件清单均有通用正反测试；原有无 Skill 路径等价。

### P1：公共多周期证据与白盒查询

扩展 RunFormal evidence，而不是教任务模型了解存储格式或自己实现解析器。

- 明确信号路径、时钟/边沿、时间窗口或采样范围、最大样本数/分页。
- 使用现有标准 reader，返回原始时间、单位、宽度、X/Z、缺失/截断/省略范围、原始证据引用。
- 未知位不可默认为0；上升沿/周期编号与工具失败深度不得默认等同。
- 不自动推断事务对应关系；若增加监视器必须显式声明规则与状态，不能以时间接近猜归属。
- 查询实际展开设计的白盒信号与宽度，预检连接，避免重复找实例名和读模板。

验收：多时钟、无时钟、80位以上、X/Z、层次同叶名、稀疏变化、大文件预算、边沿窗口、缺失信号、hash篡改与分页不漏样本。

### P1：复位契约与 Assume 审阅

- 初态复位、运行中复位、保持/释放分别表示；来自规格或明确选择，不预设所有设计仅初始复位。
- 插件适配实际工具初始化，并返回已生效范围，不让模型猜私有命令；设置失败/0有效约束给可操作诊断。
- 记录假设的规范依据、约束对象、适用配置与被排除行为；引用输出、固定延迟、含活性结论为风险提示，不用关键词禁止代替语义审查。
- 新增/收紧假设后显式展示变化；Cover大面积可达变不可达时阻止把该批当正常通过，保留回归/对照证据。
- 通用 pending/握手协议模型必须追踪接受/消费历史，不能用rsp_valid->rsp_ready冒充solicited响应。

验收：初始一次不被生成成每拍矛盾序列；允许合法背压/可变响应延迟；假设矛盾和场景排除有报告；公平性范围可追溯。

### P2：预算交互和最终报告对账

- REVIEW就绪即突出可处置清单，不必等整批停止；running目标继续。
- retry区分同策略追加预算和新策略，写具体可检查的变更；拆分目标不得删除原目标或用弱子目标代替。
- 预算、每次尝试、累计时间、未执行/排队/运行/暂缓和剩余额度直接派生，不由作者重写数字。
- 报告直接列实际假设、作用范围及未覆盖配置，避免“无公平性假设”等总结与输入矛盾；自然语言语义仍需审阅，不能声称可完全自动判断。

## 6. 建议实施顺序与比较方法

1. 先定向诊断执行与SVA预检，解决准备ERROR和单条修复绕路。
2. 再多周期证据与层次查询，减少手写解析和同一材料的重复阅读。
3. 再复位/Assume审阅，抑制环境收紧造成的伪通过。
4. 收敛预算提示、报告对账与阶段交互。

每批先固定通用输入旧/新实现对照，再Adder冒烟、再e203_biu。主要指标：实际去重调用、准备失败、修复往返、重复反例读取/表达式提交、错误归因/范围结论、未证明披露。不能以少验目标、排除合法场景或取消证据门禁换取调用数减少。

## 7. 请独立 Review 的重点

- selected/full结果隔离是否足以阻止部分运行被误用为完整验收？允许哪些并发与覆盖行为？

- 无Skill刷新作者表达式时，旧结果回放校验是否兼顾合法编辑与篡改拒绝？
- 哪些假设风险可确定性检查，哪些只能要求显式依据和人工复核？
- 当前测试是否遗漏实际工程边界？请优先给可复现实例，不以Adder专属修补代替通用设计。
